# `@cldmv/eslint-plugin-jsonv` v2.0.0 Changelog

**Release Date**: November 2026
**Release Type**: Major
**Branch**: `release/2.0.0`

---

## Overview

v2.0.0 moves `JsonvSourceCode` off the package root and onto its own subpath, `@cldmv/eslint-plugin-jsonv/source-code`. The package root now exports only the plugin, so the CommonJS entry can be the same generic shim every CLDMV package uses.

The rules, the `jsonv/jsonv` language and its options behave exactly as in v1.1.2, so lint results don't change. `require("@cldmv/eslint-plugin-jsonv")` and the ESM default import still return the plugin object. Only code that imported `JsonvSourceCode` by name from the package root has to change.

---

## 💥 Breaking Changes

### `JsonvSourceCode` moved to the `./source-code` subpath ([#109](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/109))

`JsonvSourceCode`, the `SourceCode` class the language hands to rules as `context.sourceCode`, is no longer a named export of the package root. Rule authors who use it for `instanceof` checks or type annotations import it from the new subpath:

```js
import { JsonvSourceCode } from "@cldmv/eslint-plugin-jsonv/source-code";
```

The build now emits one `dist/` file per source file instead of a single bundle, so the language and the subpath share one class and `instanceof` holds whichever way you reach it. The visitor keys moved into their own internal file; they aren't exported.

`src/index.cjs` is now the generic CLDMV shim. With one export on the root it returns that export, the plugin, so `require()` gives the same object as before.

Fixes [#108](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/issues/108), fixes [#106](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/issues/106).

## 🔧 CI & tooling

- `test:dist` only ran the CommonJS entry check, so that script is `test:cjs` now. The new `test:dist` builds and runs the Vitest suite against `dist/`, with a resolve test checking the package-name imports landed on the built tree ([#96](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/96)).
- Added the `sync-release-notes` companion workflow from the v4 template ([#103](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/103)).
- `ci.yml` synced with the CLDMV/.github v4.43.0 template, so the release PR no longer reruns the matrix on a commit its push run already tested ([#105](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/105)).

## Upgrade notes

- If you import `JsonvSourceCode` from `@cldmv/eslint-plugin-jsonv`, import it from `@cldmv/eslint-plugin-jsonv/source-code` instead.
- Nothing else changes. ESLint configs, both `import` and `require()`, work as they did in v1.1.2.
- If your scripts call `npm run test:dist` in a checkout of this repo, the CJS entry check is `test:cjs` now.
