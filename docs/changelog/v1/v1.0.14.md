# @cldmv/eslint-plugin-jsonv v1.0.14 Changelog

**Release Date**: October 2026
**Release Type**: Patch

---

## Overview

A maintenance release with no change to the plugin's behavior. Every source, test, config and workflow file now carries the uniform CLDMV file header, maintained by `@cldmv/fix-headers` from the shared `@cldmv/configs` config, and the CI `✅ Required PR Check` mirror can no longer be satisfied by a skipped run. The only edits to `index.mjs` are its new header comment.

---

## 🔧 CI & tooling

### Uniform file headers from the shared CLDMV config ([#47](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/47))

A new `fix:headers` script runs `@cldmv/fix-headers` against `.configs/fix-headers.json`, which extends `@cldmv/configs/fix-headers.json`. The first run stamped every file: `index.mjs`, `scripts/build.mjs`, the tests and the ESLint and vitest configs gained a header, and the workflow headers were rewritten to the same layout, with ISO 8601 dates and an empty comment line inside the header's opening and closing.

### A skipped PR run no longer satisfies Required PR Check ([#48](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/48))

On an in-repo feature PR, the `pull_request` run skips the `required-check` mirror job because the push run on the head branch owns the status. GitHub still posts a check run for a skipped job and treats a skipped required check as passing, so the skipped job, named `✅ Required PR Check`, could green-light the ruleset (and auto-merge) before the push run's real mirror existed. The job name is now an expression that evaluates to `✅ Required PR Check` only on the paths that own the status.
