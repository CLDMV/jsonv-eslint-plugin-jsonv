# @cldmv/eslint-plugin-jsonv v1.0.16 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/1.0.16`

## Overview

A dev-dependency release: `@cldmv/fix-headers` moves to 2.2.0 and `@cldmv/configs` to 1.2.4. The header pass was re-run for 2.1.4, and every header already matched what that version writes, so no file was restamped; the 2.2.0 and 1.2.4 bumps changed only `package.json` and the lockfile. No plugin code, published file or runtime dependency changed.

## 🔧 Dependencies

Both changes are to development dependencies. The runtime dependencies, the `eslint` peer range and the published package are unchanged.

- `@cldmv/fix-headers` `^2.1.1` → `^2.2.0` ([#54](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/54) took it to `^2.1.4`, [#57](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/57) to `^2.2.0`). Version 2.1.4 no longer writes a JavaScript comment into JSON or Markdown files, processes every repeated `--input`, and never walks dependency folders such as `node_modules`. Version 2.2.0 makes the `@Last modified by` header tag follow content edits only, so a header-only rewrite keeps the recorded editor instead of replacing it. It requires Node.js `>=22.12.0`, the same floor as the rest of the development toolchain.
- `@cldmv/configs` `^1.2.0` → `^1.2.4` ([#57](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/57)). It provides the shared `fix-headers` configuration that `.configs/fix-headers.json` extends. Version 1.2.4 turns off `forceAuthorUpdate` and `forceLastModifiedAuthorUpdate` (both were on in 1.2.0), so the shared configuration no longer overwrites the recorded author or last editor.
- Despite its title, [#54](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/54) (`restamp file headers`) changed only `package.json` and the lockfile. Neither it nor [#57](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/57) restamped any header.
