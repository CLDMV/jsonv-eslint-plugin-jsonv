## Overview

Moves the repository onto the CLDMV/.github **v4 staging-branch release flow**: feature branches merge into `next`, and a persistent `next → master` release PR carries each bundle to `master`, where it is tagged, released and published. No plugin code changed.

---

## 🔧 CI & tooling

### v4 staging-branch workflows ([#1](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/1), released in [#2](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/2))

The single hand-rolled `release.yml` is replaced by thin callers of the CLDMV/.github v4 reusable workflows:

- CI with a Node version matrix.
- The `next` / `hotfixes` release PRs, `next-reset`, and feature-PR auto-opening.
- Publishing and major-version tag maintenance.
- CodeQL, OpenSSF Scorecard and dependency review.
- Dependabot auto-merge, labeling, PR-title normalization, stale handling, branch retention, tag health, the CLA check and welcome messages.
- `v4-bootstrap` for repository settings.
