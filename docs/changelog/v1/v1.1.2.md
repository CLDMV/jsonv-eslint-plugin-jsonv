# `@cldmv/eslint-plugin-jsonv` v1.1.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/1.1.2`

---

## Overview

v1.1.2 is a development-tooling release. The test config now resolves the plugin through the `eslint-plugin-jsonv-dev` export condition the way it was meant to, and the type scripts are split into `types:check` (type-check without emitting) and `types:build` (emit declarations).

No plugin code changed. The rules, language and options are the same as in v1.1.1, so lint results don't change, and nothing changes for anyone installing the package.

---

## 🔧 CI & tooling

### Tests run against `src/` through `devCondition()` ([#92](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/92))

`.configs/vitest.config.mjs` set `test.nodeOptions` to pass `--conditions=eslint-plugin-jsonv-dev` to the test workers, but vitest has no such option, so the condition never reached them. The config now builds on `devCondition()` from `@cldmv/configs` (bumped to `^1.4.0`), which sets the resolver conditions and the worker `execArgv`, so Node's own resolver picks `src/` through the `eslint-plugin-jsonv-dev` export condition too.

### `types:check` added, `build:types` renamed to `types:build` ([#94](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/94))

- New `types:check` runs `tsc -p .configs/tsconfig.types.json --noEmit` and is what CI's type-check step runs, instead of `test:types`.
- `build:types` is now `types:build`, which emits `dist/index.d.mts`. `build` and `test:types` use the new name.
- `test:types` keeps its job: it emits the declarations and compiles the consumer test in `tests/types/` against them, as part of `build:ci`.
