## 🔧 CI & tooling

### Release-relevant CI runs are never superseded ([#3](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/3), released in [#4](https://github.com/CLDMV/jsonv-eslint-plugin-jsonv/pull/4))

`ci.yml`'s concurrency policy now distinguishes contexts:

- Feature branches still cancel superseded runs.
- Pushes to the release base branch, to `next`/`hotfixes`, and the release PRs each get a unique concurrency group per run, so they are never cancelled. The release base is derived from the `CLDMV_RELEASE_BASE` variable, falling back to the default branch.

Previously, the burst of pushes a release makes (the feature squash, the post-hotfix sync merge and the version bump) cancelled the middle run, leaving a red X on the release PR.
